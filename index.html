01 — About

Building real systems, not just learning technologies

I'm interested in building real systems — not just learning isolated technologies one at a time. My work has increasingly pulled me into backend development, mobile and web applications, databases, cloud infrastructure, Linux servers, deployment, and coordinating technical work with a team.

Most of what I do now involves understanding how a production system actually behaves — not just writing a feature, but understanding how it's built, deployed, maintained, and improved over time. That currently means working with Laravel/PHP backends and Flutter/Dart applications on top of SQL databases, and moving systems that started on shared hosting toward AWS EC2 environments running on Ubuntu Linux.

The more I work across these layers, the more interested I've become in the boundary between software and physical systems. That's part of why I've started exploring robotics, embedded systems, computer vision, electronics, and systems programming — early steps, but a direction I'm serious about.

02 — How I Think About Systems

I don't just want to write code. I want to understand the whole system.

A feature is never just a feature — it's one piece of something bigger: an interface, a backend service, a database, a server, and everything that keeps it running. I'm interested in how these layers connect, and how a real system is designed, deployed, and kept alive in production.

Layers I think about, in general:

User → Application → Backend → Database → Infrastructure → Deployment → Monitoring / Operations

In practice, on a typical Laravel / Flutter project, that looks something like this:

01 Client / User
02 Flutter / Web Application
03 Laravel Backend
04 SQL Database
05 AWS / Linux Infrastructure
06 Deployment & Operations

Note: this isn't the architecture of every project — it's an illustration of the kind of system I work with and want to understand more deeply, end to end.

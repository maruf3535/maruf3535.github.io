01 — About

How I got here

I care more about building things that actually run in production than about collecting technologies for their own sake. My work has increasingly pulled me into backend development, mobile and web applications, databases, cloud infrastructure, Linux servers, deployment, and — more and more — coordinating that work across a team.

In practice that means Laravel and PHP on the backend, Flutter and Dart for the applications on top of it, SQL underneath, and, for a lot of what I'm doing lately, moving systems that started on shared hosting onto AWS EC2 running Ubuntu. How something is built is only half the job. The other half is how it's deployed, maintained, and kept working.

The more of these layers I work across, the more curious I get about where software ends and hardware begins. That's why I've started exploring robotics and embedded systems on the side. Early days, but a direction I'm taking seriously.

02 — How I Think About Systems

I don't just want to write code. I want to understand the whole system.

A feature is never just a feature. It's one piece of something bigger — an interface, a backend service, a database, a server, and everything that keeps it running. I'm interested in how those layers connect, and how a real system gets designed, deployed, and kept alive once it's live.

On a typical Laravel / Flutter project, that looks like this:

01 Client / User
02 Flutter / Web Application
03 Laravel Backend
04 SQL Database
05 AWS / Linux Infrastructure
06 Deployment & Operations

Not every project looks exactly like this — but this is the shape I'm usually trying to understand, end to end.
